# TIL

C++와 Unreal을 배우면서 적은 메모와 프로젝트 기록을 모은 정적 사이트다. 작성 기준은 [AGENTS.md](AGENTS.md)를 따른다.

## 어디서 시작할까

- **개인 자료 저장소:** `local/`은 별도 비공개 Git 저장소다. 공개 TIL의 업로드에는 포함되지 않으며, 개인 자료 저장은 별도로 진행한다. 새 PC의 바로가기는 `local/바로가기 만들기.cmd`로 다시 만든다.
- **PC에서 바로 열기:** 루트의 `00 시작하기/`에 공개 사이트, 관리 도구, 로컬 미리보기, 새 자료와 저장 데이터 바로가기를 모았다. 번호 순서대로 찾으면 된다. 이 폴더는 공개되지 않는다.
- **새 파일을 정리하고 싶을 때:** PC의 `local/inbox/`에 넣고 정리를 요청한다. 사용법은 그 폴더의 `README.md`에 있다.
- **글을 직접 작성·수정할 때:** `local/manage/start.cmd`를 실행한다. 초안 → 검증·미리보기 → 적용 → commit/push 순서로 확인한다.
- **공개 글을 찾을 때:** 날짜별 글은 `data/연도/월/`, 정리 자료는 `data/materials/`, 알고리즘은 `data/algorithms/`의 문제별 파일을 본다.
- **원본·정리 내역을 찾을 때:** `local/README.md`에서 폴더별 위치를 확인한다. `local/`은 별도 비공개 저장소로 백업하며 GitHub Pages에는 포함되지 않는다.

## 화면

- **홈**: 대표 프로젝트, 학습 기록·알고리즘·자료실 입구, 전체 검색과 최근 학습 기록을 보여준다.
- **프로젝트**: Project Priest는 소개·담당 역할·핵심 작업·기존 TIL을 연결하고, 돌아보기는 별도 본문으로 연다. 다른 프로젝트는 기존 작업 기록을 묶어 보여준다. 대표 프로젝트 정보는 `data/projects.js`에서 관리한다.

- **날짜별 기록 57개**: 날짜·제목·프로젝트로 찾는다. 큰 주제로 비슷한 태그를 묶어 좁힐 수 있다. 상단에서 연·월·일 순서로 시작일과 종료일을 고르면 겹치는 글이 나온다. 한쪽만 골라도 되며 선택한 기간은 화면에 표시된다. 작성일이 불분명한 메모·프로젝트 자료 4개는 관련 기록 기간에 묶고, 정확한 학습일과 구분해 표시한다.
- **정리 자료 19개**: 기존 자료구조 문서, Velog 개념 정리, 수업 메모다. 종류·분야·글 상태와 검색으로 찾는다. 여러 분야를 고르면 모두 해당하는 자료가 나온다.
- **알고리즘 41개**: 문제 원문, 풀이 과정과 코드, 확인된 채점 결과를 보여준다. 문제 유형·풀이 상태와 검색으로 찾는다. 확인된 LeetCode 제출은 제출 내역 링크도 제공한다. 로그인해야 열리는 제출 페이지가 있을 수 있다.

검색·날짜·태그·정렬을 목록 위에 표시한다. 주제·활동·프로젝트 등의 추가 조건과 날짜 조건을 함께 사용할 수 있다. 목록으로 돌아오면 선택한 조건을 유지한다. 모바일에서는 날짜·태그 선택 창과 목차를 접었다 펼칠 수 있다. 긴 본문의 목차는 PC에서 오른쪽에 고정된다.

`index.html`을 브라우저에서 열어 사용할 수 있고 별도 빌드는 필요 없다. 주소의 `#record=기록ID`, `#material=자료ID`, `#algorithm=문제ID`로 상세 글을 바로 연다. 각 목록 주소는 `#list`, `#library`, `#algorithms`다.

홈은 `#home`, 프로젝트 목록은 `#projects`, Project Priest 상세는 `#project=priest`, 돌아보기는 `#reflection=priest`다. 로컬 관리 도구에서도 같은 공개 화면을 미리 본다. 프로젝트 소개·돌아보기 편집은 현재 파일에서 하며 관리 화면의 기존 글 편집 대상에는 추가하지 않았다. 비공개 원본 영상은 공개 폴더에 복사하지 않는다.

## 글과 원본

짧은 메모는 짧게 둔다. 원본에 없는 회고나 다음 계획을 덧붙이지 않고, 실제 작업과 코드, 막힌 부분을 직접 적는다. 날짜별 글은 문장 길이에 상관없이 작성된 문단을 모두 보여준다. 질문이나 남은 문제는 필요한 글에만 둔다.

Unreal 작업 이미지 21장은 관련 글 7개에 들어 있다. Velog 이미지 주소와 원문 링크를 유지한다. 자료실의 자료구조 원문 링크는 보관 원본과 같은 내용의 공개용 HTML 사본으로 연결된다. Velog 자료는 원문으로 연결하고, 공개 주소가 없는 수업 메모는 원본 파일 이름을 표시한다.

알고리즘의 제출 코드와 채점 상태는 보존한다. 수정안이나 참고 예제가 당시 제출과 다른 경우 제목과 설명에서 구분한다. 제출이 통과했어도 배열 범위 문제나 문제 조건과 다른 부분이 남아 있으면 함께 적는다. 코드만 남은 문제에는 당시 생각이나 시행착오를 만들어 붙이지 않는다.

Git 기반 프로젝트 글의 날짜는 코드 변경일이다. 실행 근거가 없는 기능을 실행 성공으로 표시하지 않는다. 날짜 없는 프로젝트 ZIP은 관련 수업·프로젝트 기록 기간에 함께 배치하고, ZIP의 정확한 작업일로 취급하지 않는다. CH3_1, CH3_2, CH3는 **챕터 3 개인 프로젝트** 필터로 묶으며 원래 단계와 저장소 링크는 유지한다. CH3_3는 포함하지 않는다.

| `assets/filters.js` | 공통 태그·날짜 조건 |
| `data/projects.js` | 대표 프로젝트 소개·역할·작업 과정·돌아보기 |
| `data/manifest.js` | 날짜별 기록 목록 |

| `data/undated/`, `data/project-period/` | 날짜 없는 메모와 프로젝트 전체 기록 |
| `data/library-index.js`, `data/materials/자료ID.js` | 자료실 목록과 본문 |
| `data/algorithms/문제.js` | 문제별 설명·시행착오·코드·결과 (직접 수정하는 본문) |
| `data/algorithms.js` | 본문에서 생성한 목록·검색 정보와 파일 경로 |
| `data/guides/stl-reference.html` | 자료구조 원문 공개용 사본 |
| `local/` | Git에서 제외한 원본 사본, 작업 자료, 검증 도구 |

새 날짜별 글은 고유 `id`, `date`, `title`, `study_content`와 필요한 경우 `learning_process`, `questions`, `mistakes_or_difficulties`, `images`, `velog`, `repository`, `references`를 적는다. `window.TIL_FILES[파일경로]`에 저장하고 목록에도 같은 ID·제목·분류·파일경로를 등록한다. `summary`는 검색과 목록 데이터용이며 날짜별 카드에서는 표시하지 않는다.

`unreal-containers`는 아직 게시하지 않은 초안이다. 예제 실행 여부와 Velog 게시 여부를 구분한다. 오래된 생성·마이그레이션 도구는 현재 편집 내용을 덮어쓸 수 있으므로 다시 실행하지 않는다.

## 검증

저장소 루트에서 실행한다.

```text
node local/tools/test-navigation.cjs
node local/tools/verify-daily.cjs
node local/tools/verify-library.cjs
node local/tools/test-project-site.cjs
git diff --check
```

화면은 데스크톱과 모바일에서 긴 글, 이미지, 카드 전체의 hover·focus, 날짜 범위, 필터, 상세 이동과 외부 링크를 함께 확인한다. 커밋·푸시·병합은 사용자가 해당 작업에서 직접 요청했을 때만 실행한다.

### 알고리즘 파일 수정

문제 하나를 파일 하나에 둔다. 예: `data/algorithms/lc-155-min-stack.js`.
설명·코드·결과를 더 잘게 나누지 않으며 자료실도 글당 한 파일로 두고, 프로젝트 파일은 그대로 둔다.
기존 문제 ID와 `#algorithm=lc-155` 같은 주소는 바뀌지 않는다.

관리 화면에서 저장하면 문제 본문과 목록이 함께 갱신된다. 파일을 직접 수정하거나 새 파일을 추가했다면 `node local/tools/sync-algorithms.cjs`로 목록을 갱신한다. `--check`를 붙이면 파일을 바꾸지 않고 일치 여부만 검사한다. 문제 파일은 기존 형식을 복사하고 고유 ID를 지정한다. 목록 파일은 직접 편집하지 않는다.

자료실 본문은 `data/materials/`에 글당 한 파일로 보관한다. 직접 수정한 뒤 `node local/tools/sync-materials.cjs`로 목록을 갱신한다. `--check`는 일치 여부만 확인한다. 관리 화면에서는 본문과 목록이 함께 저장된다. 원본 자료구조 문서와 비공개 원본은 기존 위치를 유지한다.
