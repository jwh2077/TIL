# C++ 기술 노트 — 게임 개발 학습

> 실제 학습 주제와 프로젝트에서 활용한 개념을 연결한 복습 노트입니다. 모든 항목이 특정 프로젝트의 최종 코드에 그대로 반영되었다는 뜻은 아닙니다.

## 포인터와 참조

- **포인터**는 다른 객체의 주소를 저장하는 변수입니다. `nullptr`로 비울 수 있고 다른 주소를 가리키게 할 수 있습니다.
- **참조**는 기존 객체의 별칭입니다. 초기화 시 대상이 필요하고 일반적인 참조는 다른 대상으로 다시 연결하지 않습니다.
- 포인터 변수에 `nullptr`를 대입하는 것과 포인터가 가리키는 객체의 값을 바꾸는 것은 서로 다른 동작입니다.

```cpp
int health = 100;
int* target = &health;
*target = 80;       // health의 값 변경
target = nullptr;   // target의 주소값만 비움
```

## 상속과 컴포지션

- **상속(is-a):** 공통 인터페이스나 기본 동작을 확장하는 관계
- **컴포지션(has-a):** 객체가 별도 기능 객체를 보유하고 조합하는 관계
- 선택 기준은 단순히 '기능을 뗄 수 있는가'뿐 아니라 책임, 결합도, 변경 가능성입니다.

TextRPG에서는 직업별 동작을 상속·다형성과 연결해 학습했고, Unreal에서는 캐릭터와 별도 컴포넌트의 역할 분리를 검토했습니다.

## 가상 함수와 다형성

기본 클래스 포인터·참조를 통해 파생 클래스의 재정의된 동작을 호출하려면 `virtual` 함수가 필요합니다. 기반 클래스가 다형적으로 삭제될 수 있다면 가상 소멸자를 고려합니다.

## Unreal C++에서 함께 확인할 것

- `UCLASS`, `USTRUCT`, `UPROPERTY`, `UFUNCTION`은 Unreal Header Tool과 리플렉션 체계에 연결됩니다.
- 헤더의 전방 선언과 실제 타입 정의가 필요한 위치를 구분합니다.
- `Build.cs`의 모듈 의존성과 `#include` 경로를 함께 확인합니다.
- UObject·Actor 참조는 수명과 유효성을 확인하고, 포인터의 존재만으로 객체의 유효성을 단정하지 않습니다.
