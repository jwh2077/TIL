# 문제 해결 기술 노트 — 원인 분석과 검증

> 공개된 프로젝트 작업 사례에서 반복적으로 나타난 디버깅 관점을 정리했습니다.

## 기본 절차

1. **증상:** 어떤 화면·로그·행동이 예상과 다른지 기록합니다.
2. **재현:** 입력, 역할(서버·클라이언트), 프레임 조건 등 재현 조건을 확인합니다.
3. **경로:** 관련 함수 호출, 컴포넌트, 데이터 전달 흐름을 좁힙니다.
4. **가설 검증:** 로그나 상태 출력으로 한 번에 하나씩 확인합니다.
5. **수정:** 원인과 직접 관련된 범위만 변경합니다.
6. **재확인:** 기존 동작과 문제가 발생한 조건을 다시 테스트합니다.

## 사례 1 — 공격 모션은 재생되지만 피해가 누락됨

- **확인된 현상:** 프레임 조건에 따라 공격 판정이 누락된 기록이 있음
- **시도:** Sphere, Box, Overlap 결과 저장 방식 검토
- **발표 자료에 기록된 개선:** ApplyAttack Notify 시점에 공격 범위를 검사
- **추가 검증:** 최종 코드의 판정 대상, 중복 타격 방지, 서버 실행 여부, 실제 테스트 결과

## 사례 2 — Mesh를 숨겼는데 화면에 남음

- **현상:** C++ `GetMesh()` 대상과 Blueprint에서 실제 렌더링하는 Mesh가 다름
- **접근:** 사망 처리 경로에서 실제 표시 중인 컴포넌트를 확인
- **개선 기록:** Blueprint에서 실제 Mesh를 숨기도록 변경
- **일반화:** 참조가 유효하다는 사실과 원하는 화면 대상이라는 사실은 다름

## 사례 3 — 출발 속도와 가속 값의 차이

- **확인된 현상:** Don't Drop에서 출발 속도를 올리자 처음 빠르게 움직인 뒤 급격히 느려지는 문제가 발생했습니다.
- **분석:** 시작 시 설정하는 속도와 입력을 누르는 동안 증가하는 이동 세기는 서로 다른 값입니다.
- **조치:** DataTable의 출발 속도·가속 시간·최소 입력 세기를 구분하고, CharacterMovement 설정과 함께 조정했습니다.
- **검증 한계:** 이 조정이 최종 네트워크 이동을 안정화했다는 결과까지는 확인되지 않았습니다.

## 사례 4 — 멀티플레이 동작이 클라이언트마다 다름

이 항목은 **실제 해결 완료 사례가 아니라 테스트 체크리스트**입니다.

- 입력이 로컬에서 발생했는지 확인
- Server RPC가 실행됐는지 로그 확인
- Actor Owner·Authority·Replication 상태 확인
- 클라이언트별 호출 횟수와 시점 비교
- 서버에서 변경한 값이 실제로 복제되는지 확인

확인되지 않은 수치나 성공 여부를 추가하지 않습니다.
