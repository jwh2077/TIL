# 게임 클라이언트 개발 포트폴리오

**희망 직무:** C++ · Unreal Engine 게임 클라이언트 개발  
**문서 범위:** 직접 참여한 프로젝트와 공개 학습 기록에 근거한 기술 포트폴리오

## 01. 개발 경험 요약

C++과 Unreal Engine을 학습하며 게임플레이 기능과 멀티플레이 구조를 구현하고 있습니다. 팀 프로젝트에서는 **적 AI·무기 파츠**와 **캐릭터 이동·입력** 작업을 맡았고, 개인 실습에서는 **C++ 객체지향 구조**, **게임 규칙**, **네트워크 통신**을 다뤘습니다.

기능을 연결할 때 예상과 다른 동작이 발생하면 입력, 데이터, 호출 경로를 나누어 확인하고, 시도한 방법과 확인된 결과를 별도로 기록하고 있습니다.

### 다룬 기술

| 구분 | 프로젝트에서 다룬 내용 |
| --- | --- |
| C++ | 상속·다형성, 포인터·스마트 포인터, STL, 클래스 책임 분리 |
| Unreal Engine 5 | Actor·Component, Blueprint, Enhanced Input, CharacterMovementComponent |
| 게임 AI | Behavior Tree, Blackboard, AI Perception, 이동·공격 조건 |
| 데이터 | DataTable, GameInstance, 아이템·파츠 데이터 연결 |
| 멀티플레이 학습 | GameMode, PlayerController·PlayerState, RPC·Replication |

기술 숙련도를 임의로 점수화하지 않았습니다. 프로젝트 활용과 학습 중인 내용을 구분해 서술합니다.

## 02. 주요 프로젝트

### Project Priest — 적 AI와 무기 파츠

**형태** 팀 액션 게임 / Unreal Engine 5 / C++  
**기록 기간** 2026.09 / 팀 발표 자료와 학습 기록 확인

**담당 업무**

- Behavior Tree와 Blackboard를 사용해 적의 순찰·감지·추적·공격 흐름을 연결했습니다.
- 무기 파츠의 슬롯별 장착, 데이터 참조 및 능력치·UI 연결 작업을 맡았습니다.
- 근접 공격에서 애니메이션 재생과 피해 적용이 일치하지 않는 문제를 조사했습니다.
- 사망 처리 시 C++에서 참조한 Mesh와 실제 Blueprint Mesh가 다른 문제를 확인했습니다.

**대표 문제 해결 — 공격 판정 누락**

공격 모션은 재생되지만 일부 조건에서 피해가 들어가지 않았습니다. Overlap으로 대상을 보관하는 방식과 충돌 범위 설정을 점검했고, 9월 25일 기록에서는 공격 Box 높이를 조정한 뒤 판정이 더 안정적으로 들어오는 현상을 확인했습니다. 팀 발표 자료에는 공격 Notify 시점의 범위 검사 방식도 해결 과정으로 정리되어 있습니다. 다만 두 시점의 코드가 최종본에서 어떻게 합쳐졌는지는 별도 검증이 필요합니다.

**확인 가능한 결과** 게임 플레이 영상에는 일반 전투·인벤토리·구역 이동·보스전이 담겼고, 팀 발표 기록이 있습니다.

### Don't Drop — 캐릭터 이동과 전투 입력

**형태** 리슨 서버 기반 팀 대전 게임 / Unreal Engine 5.6 / C++  
**기록 기간** 2026.10~11 / 개발 진행 기록

**담당 업무**

- CharacterMovementComponent의 이동·점프 설정을 DataTable 값과 연결했습니다.
- 방어구 무게에 따라 최대 속도를 다시 계산하고, 방어구 상태 변경 이벤트를 받아 갱신했습니다.
- 이동 입력 경과 시간에 따라 입력 세기를 조절하고, 출발 속도·가속·감속·마찰을 조정했습니다.
- 공격·가드 입력을 전투 컴포넌트 호출로 이어 주는 부분을 작성했습니다.

**대표 문제 해결 — 출발 속도와 가속의 차이**

출발 속도만 크게 올렸을 때 처음에는 빠르게 움직였다가 급격히 느려져 대시처럼 보였습니다. 시작 순간의 속도와 입력 유지 시간에 따른 가속을 구분해 조정했고, 무게별 설정을 별도로 관리했습니다. 이는 **개발·조정 과정**의 기록이며, 최종 멀티플레이 이동 일치 여부를 완료 성과로 주장하지 않습니다.

**상태 구분** 관전 기능은 직접 시도했지만 작동하지 않았고, 팀원의 기존 구현을 확인한 뒤 개인 테스트 코드를 제거했습니다. 엑셀 기반 설정 연동은 구상 단계입니다.

### ChatX — 채팅과 숫자 야구 멀티플레이

**형태** Unreal C++ 개인 실습 / 2026.10

- PlayerController를 통한 Server·Client RPC 호출 관계를 학습하고 채팅 전달 흐름을 작성했습니다.
- 숫자 야구의 입력 검증, Strike·Ball 계산과 시도 횟수·승패 처리를 GameMode에 배치했습니다.
- PlayerState의 플레이어 이름·시도 횟수와 알림 데이터 복제 설정을 다뤘습니다.
- 실행 환경·Owner·RPC 호출 위치에 따른 동작 차이를 기록했습니다.

**검증 범위** 소스 작성 및 학습 기록은 확인됩니다. 모든 외부 환경에서의 세션 안정성이나 게임 규칙의 완전한 테스트 성공을 의미하지 않습니다.

## 03. C++ 기초와 팀 협업

### 팀 TextRPG — 상점·아이템 관리

**형태** C++ 팀 프로젝트 / 2026.07~08

Shop과 Item의 책임을 분리하고 `std::unique_ptr<Item>`을 이용한 아이템 관리를 다뤘습니다. 구매·판매 기능과 Logger를 통한 전투·아이템·골드 데이터 집계 작업 기록이 있습니다. Git의 브랜치·PR·병합·충돌 해결을 처음 경험하면서, 기능뿐 아니라 팀 사이의 역할과 코드 경계도 조율했습니다.

### 그 밖의 개인 실습

- **개인 TextRPG:** 직업 선택과 `Player*` 기반 상속·다형성 적용
- **FirstFPS:** Blueprint 기반 이동·발사·HUD·아이템·게임 진행
- **챕터 3 개인 프로젝트:** Pawn 조작, 움직이는 발판, 아이템·웨이브·HUD 연결
- **CX:** 채팅 기록 보관과 신규 접속자 전달 흐름을 작성한 네트워크 실습

## 04. 문제 해결과 협업 방식

**실행 위치 확인:** 멀티플레이 기능은 입력을 받는 클라이언트, 권한이 있는 서버, 값을 전달받는 클라이언트를 나눠 생각합니다.

**데이터 흐름 확인:** 코드에 값이 있어도 실제 컴포넌트에 적용되지 않으면 기능이 달라지지 않는다는 점을 이동 설정 작업에서 확인했습니다.

**담당 간 인터페이스 조율:** 무기 파츠와 UI, 방어구 상태와 이동처럼 담당이 다른 기능 사이에서 전달할 값과 호출 시점을 조정했습니다.

**남은 과제:** 최종 코드와 시연에서 확인되지 않은 동작, 네트워크 동기화 성능, 정량적 개선 수치는 실적으로 기재하지 않습니다.
