# 게임 클라이언트 개발 포트폴리오

**지원 분야** C++ · Unreal Engine 게임 클라이언트 개발  
**자료 기준** 공개 프로젝트·학습 기록, 2026-11-09까지 확인

## 01. 작업 방향

C++과 Unreal Engine을 사용해 게임플레이 기능을 배우고 구현했습니다. 팀에서 맡은 기능을 다른 시스템과 연결할 때 생긴 문제를 실행 시점·데이터 전달·컴포넌트 역할로 나눠 확인했습니다.

**중심 경험** 적 AI와 공격 판정 / 무게에 따른 캐릭터 이동 / 서버의 게임 규칙과 RPC / C++ 아이템 관리

## 02. 대표 프로젝트

### 01. Project Priest

**형태·상태** 팀 액션 게임 · 팀 발표 완료  
**기록 범위** 2026.09 · 팀 발표 09.29  
**담당** 적 AI · 무기 파츠 · UI 데이터 연동  
**기술** Unreal Engine 5 / C++ / Behavior Tree / Blackboard

순찰·감지·추적·공격을 연결하고, 무기 파츠 데이터를 능력치와 UI에 전달하는 기능을 담당했습니다.

**주요 작업** AIController·Behavior Tree·Blackboard를 연결해 행동 조건을 구성 / 파츠 정보의 저장·참조·장착 데이터와 UI 전달 경로 점검 / 공격 Overlap·Anim Notify·Mesh 사망 처리 문제 조사

**기술적 문제** 공격 모션이 보이지만 피해가 적용되지 않는 구간이 있었고, 플레이어를 놓치는 순간 참조를 비우면 전투 흐름이 끊겼습니다.

**확인된 내용** 적 AI와 파츠 작업 및 2026.09.29 팀 발표 기록이 있습니다. 플레이 영상에는 전투·인벤토리·구역 이동·보스전이 담겼습니다.

**추가 검증** Collision 수정 후의 확정 테스트 결과와 최종 공격 판정 구현의 일치 여부는 확인되지 않았습니다. 감지 상실 보완 일부는 설계 검토 단계입니다.

### 02. Don’t Drop

**형태·상태** 리슨 서버 팀 대전 게임 · 개발 기록 · 완료 미확인  
**기록 범위** 2026.10.29–11.09 · 확인된 기록  
**담당** 캐릭터 이동 · 입력 · 방어구 무게 연동  
**기술** Unreal Engine 5.6 / C++ / CharacterMovement / Enhanced Input

이동 설정을 DataTable에서 적용하고 방어구 무게·입력 유지 시간·전투 요청이 캐릭터 이동에 반영되도록 작업했습니다.

**주요 작업** FPlayerDataRow·FPlayerMovementTuningRow 설정을 CharacterMovementComponent에 적용 / 무게 변경 이벤트와 최대 속도 재계산 연결 / 공격·가드 입력을 전투 컴포넌트 요청으로 전달

**기술적 문제** 출발 속도를 크게 주면 처음 빠르게 이동했다가 급격히 느려져 대시처럼 보였습니다. 테이블에 정의된 AirControl 등의 값이 실제 컴포넌트에 반영되지 않은 부분도 살폈습니다.

**확인된 내용** 캐릭터 코드와 데이터 테이블 병합 후 빌드가 통과한 기록 및 가드 C++ 로그 확인 기록이 있습니다. 출발 속도 문제는 직접 플레이에서 관찰했습니다.

**추가 검증** 최종 원격 클라이언트 이동 일치·게임 완성은 확인되지 않았습니다. 관전 테스트 코드는 작동하지 않아 제거했고 엑셀 설정 연동은 구상 단계입니다.

### 03. ChatX · 숫자 야구

**형태·상태** 개인 멀티플레이 실습 · 코드 작성 · 통합 검증 미확인  
**기록 범위** 2026.10.02–10.12 · 학습 기록  
**담당** 숫자 야구 규칙 · 채팅 RPC · 상태 복제  
**기술** Unreal Engine / C++ / GameMode / RPC

게임 규칙 판정을 서버 GameMode에 배치하고, PlayerController의 채팅 메시지와 PlayerState 복제를 학습하며 코드를 작성했습니다.

**주요 작업** 1~9 중 중복 없는 세 숫자 생성·입력 검증·Strike/Ball 판정 작성 / 서버에서 Controller를 순회하며 각 소유자에게 Client RPC 전달 / 이름·시도 횟수의 PlayerState 복제 설정과 알림 UI 흐름 작성

**기술적 문제** 특정 PlayerController는 다른 클라이언트에 없으므로 NetMulticast만으로 모두에게 메시지를 전달하기 어려웠습니다.

**확인된 내용** 10월 12일 메시지 전달·숫자 야구 판정 및 복제 코드 작성과 해당 커밋 기록이 있습니다.

**추가 검증** 코드 작성은 확인되지만 전체 게임의 실행 성공·외부 네트워크 안정성은 기록만으로 단정하지 않습니다.

### 04. 팀 TextRPG

**형태·상태** C++ 콘솔 RPG 팀 프로젝트 · 팀 프로젝트 마무리  
**기록 범위** 2026.07.29–08.05 · 작업 기록  
**담당** 상점 구매·판매 · Item 관리 · Logger  
**기술** C++ / STL / std::unique_ptr / Git

상점 구매·판매 기능을 맡아 Shop과 Item의 책임을 나누고, std::unique_ptr<Item>을 이용한 아이템 관리와 팀 코드 병합을 경험했습니다.

**주요 작업** 상점 아이템 구매·판매 흐름 구현 및 수정 / Shop·Item 클래스 역할 분리와 unique_ptr 기반 아이템 관리 / 전투·아이템·골드 Logger 집계 및 Git 브랜치·PR 협업

**기술적 문제** 구매와 판매, Item의 관리 책임이 섞이면 구조가 복잡해졌고, 팀 통합 시 Git 병합·충돌과 역할 경계 조정이 필요했습니다.

**확인된 내용** 2026.08.03 리팩터링 기록과 08.05 팀 프로젝트 마무리·협업 회고가 있습니다.

**추가 검증** 메모리·성능 향상 수치를 측정하지 않았습니다. 팀의 모든 기능을 단독 개발한 것으로 표시하지 않습니다.

## 03. 그 밖의 학습과 실습

- **CX · 차량 프로젝트:** 채팅 데이터와 새 접속자 기록 전달. ChatX와 구분되는 별도 프로젝트이며 차량 게임 전체 개발·완료를 주장하지 않습니다.
- **FirstFPS:** Blueprint 기반 이동·발사·HUD·아이템. 초기 Blueprint 게임플레이 실습
- **개인 TextRPG:** 직업 파생 클래스·Player*·STL. C++ 상속·다형성 학습
- **챕터 3 개인 프로젝트:** Pawn·아이템·웨이브·HUD. 엔진 게임플레이 구조 학습

## 05. 검증 기준

팀 프로젝트 결과와 개인 담당 범위는 다르게 기록합니다. **구현 시도·실행 관찰·최종 검증**을 구분하며, 성능 수치와 네트워크 동작 성공처럼 확인되지 않은 결과는 기재하지 않습니다. 실제 구현과 기록이 달라질 수 있는 세부 내용은 지원 전 최종 코드를 다시 대조해야 합니다.

이 문서에는 이름, 주소, 전화번호, 학력 및 개인 지원 이력을 넣지 않았습니다.
