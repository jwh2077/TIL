# 프로젝트 경험과 문제 해결 사례

> 포트폴리오에 기재할 수 있는 사례를 실제 작업 기록 중심으로 정리했습니다. 프로젝트 완료와 개별 기능의 최종 코드 검증은 서로 다른 기준으로 판단합니다.

## 1. Project Priest — 적 AI와 무기 파츠

**프로젝트:** Unreal Engine 5 기반 3D 액션 게임 팀 프로젝트  
**기술:** C++, Behavior Tree, Blackboard, DataTable  
**담당:** 적 AI, 무기 파츠, 공격 판정, UI 데이터 연결

### 사례 A. 적 행동의 연결

- **목표:** 적이 순찰하다가 플레이어를 감지하면 추적하고, 공격 가능 거리에서 공격하도록 구성
- **접근:** Behavior Tree의 Task·Decorator와 Blackboard 조건을 사용하여 행동을 나누고 전환을 연결
- **어려움:** 개별 동작보다 순찰·추적·공격 사이의 조건과 전환이 복잡했음
- **확인 방법:** 실행 흐름과 Blackboard 값을 보며 조건을 점검하고 플레이 테스트를 반복
- **남은 주의점:** 작업 기록만으로 모든 예외 상황의 최종 동작을 보장할 수는 없음

### 사례 B. 공격 판정 누락

- **현상:** 공격 모션은 재생되지만 특정 프레임 조건에서 피해가 누락됨
- **시도:** Sphere 기반 판정, Box 기반 판정, Overlap 결과 저장 등 여러 접근을 검토
- **정리된 해결 방향:** 발표 자료에는 ApplyAttack Notify 시점에 공격 범위를 검사하는 방식으로 해결한 과정이 기록됨
- **검증 한계:** 최종 공격 범위 수치 및 제출 코드의 모든 세부 사항은 이 자료만으로 확정하지 않음

### 사례 C. 무기 파츠와 UI 연결

- **목표:** 파츠 장착에 따라 무기 능력치를 변경하고 UI에 표시
- **접근:** 슬롯별 파츠 정보와 DataTable·GameInstance 기반 데이터를 다루며 UI 담당자와 필요한 값을 조율
- **협업 포인트:** 담당 기능을 독립적으로 만드는 것뿐 아니라 데이터가 넘어가는 지점을 함께 맞춤
- **검증 한계:** PartSubsystem으로의 이전 시도는 기록되어 있으나 최종 반영 범위는 별도 확인 필요

### 사례 D. 사망 처리 시 Mesh 불일치

- **현상:** C++의 GetMesh()로 숨기려던 대상과 화면에 보이는 Blueprint의 실제 Mesh가 달랐음
- **조치:** 사망 처리 흐름에서 Blueprint 쪽 실제 Mesh를 대상으로 숨김 처리하도록 조정
- **배운 점:** 코드에서 참조하는 컴포넌트와 최종 렌더링 대상이 일치하는지 확인해야 함

## 2. ChatX — 숫자 야구 멀티플레이 실습

- **범위:** 채팅과 숫자 야구 규칙을 활용한 Unreal C++ 네트워크 실습
- **주요 학습 주제:** GameMode, PlayerController, 서버·클라이언트 실행 위치, RPC, 플레이어 간 메시지 전달
- **면접 설명 포인트:** 규칙 판정은 어디서 수행하는지, 특정 클라이언트에게 전달할 메시지와 전체에 알릴 이벤트를 어떻게 구분하는지
- **주의:** 학습 기록 및 시연 영상의 존재만으로 외부 네트워크 환경에서의 완전한 안정성을 주장하지 않음

## 3. Don't Drop — 캐릭터·조작 및 네트워크 구조

- **범위:** 리슨 서버 기반 서바이벌 대전 게임의 캐릭터·조작 파트
- **기술 주제:** CharacterMovementComponent, Enhanced Input, Authority/Ownership, 전투 시스템과의 인터페이스
- **설계상 고려:** 이동·카메라의 로컬 처리와 서버 권한 동작을 구분하고, 전투 상태가 이동 제약에 미치는 영향을 연결
- **상태 표기:** 설계·개발·테스트 기록을 구분하며, 저장소에서 검증되지 않은 완료·배포·동기화 성공을 주장하지 않음
