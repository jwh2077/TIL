# 프로젝트별 기술 경험

**작성 기준:** 업무 범위와 문제 해결 과정을 우선하고, 시도·확인·미검증을 구분합니다. 아래는 개인 기여 내용 중심의 공개 정리본입니다.

## 01. Project Priest

**분류** Unreal Engine 5 팀 액션 게임 / C++  
**담당** 적 AI · 무기 파츠 · UI 데이터 연동 · 전투 판정  
**시점** 2026년 9월 작업·발표 기록

### 적 AI 행동 전환

**목표** 적이 순찰하고, 플레이어를 감지하면 추적·공격하며, 대상을 잃었을 때 상황에 맞게 행동하도록 구성했습니다.

**구현 과정** EnemyCharacter와 적 종류별 클래스를 나누고, AIController·Behavior Tree·Blackboard를 연결했습니다. 플레이어 감지 여부와 마지막 위치를 고려해 행동 전환을 정리했습니다.

**어려움과 조치** 감지 대상 포인터를 즉시 비우면 전투가 끊기는 흐름을 확인하고, 현재 감지 여부와 마지막 위치·수색 단계를 나눠 검토했습니다.

**검증 한계** 수색 3회 후 복귀 흐름은 설계·수정 기록이 있으며, 모든 예외 상황의 최종 검증은 별도로 확인해야 합니다.

### 근접 공격 피해 판정

**증상** 공격 애니메이션이 실행되지만 간헐적으로 피해가 적용되지 않았습니다.

**확인 과정** BoxComponent의 Begin·End Overlap, 공격 Notify, 저장한 대상의 유효성, 충돌 Box 높이를 나눠 점검했습니다.

**관찰 결과** 9월 25일 기록에는 Box 높이 조정 후 판정이 더 안정적인 사례가 있습니다. 팀 발표에는 Notify 시점 직접 범위 검사 접근이 정리되어 있습니다.

**남은 확인** 최종 제출 코드의 판정 방식과 프레임별 안정성은 별도 대조가 필요합니다.

### 무기 파츠와 UI 연동

**담당** 파츠 데이터의 저장·참조, 슬롯별 장착과 능력치 반영, UI 담당자와의 값 연결

**구조** DataTable, GameInstance, PartInstance·PartManager 참조를 따라 Blueprint에서 필요한 데이터를 가져오는 경로를 확인했습니다.

**협업 포인트** 기능별 담당이 다르므로 데이터 이름·형식·갱신 시점을 함께 맞춰야 했습니다.

**유의** PartSubsystem 이전 작업은 검토 기록이 있으나 최종 이관 완료를 단정하지 않습니다.

## 02. Don't Drop

**분류** Unreal Engine 5.6 · C++ 팀 대전 게임 / 리슨 서버 개발  
**담당** 캐릭터 이동·입력, 방어구 무게와 이동 연동  
**시점** 2026년 10월 말~11월 9일 기록

### 데이터 기반 이동 설정

- `FPlayerDataRow`와 별도의 이동 조정 값을 통해 기본 이동·가속·마찰·공중 제어 설정을 구분했습니다.
- DataTable 행을 읽어 CharacterMovementComponent에 실제 적용하는 경로를 만들었습니다.
- 방어구 상태 변경 이벤트를 받아 최대 이동 속도를 무게에 맞춰 다시 계산했습니다.
- 이동 입력 경과 시간에 따른 입력 세기 조절과 출발 속도를 구분해 테스트했습니다.

### 직접 관찰한 문제

**문제** 출발 속도만 높이면 처음에 빠르게 움직였다가 급격히 느려졌습니다.

**분석** 시작 속도와 입력 세기의 단계적 증가가 서로 다른 동작이며, 설정을 함께 조정해야 한다는 점을 확인했습니다.

**후속 작업** 무게에 따른 가속·감속·마찰·중력 배율을 다루고, 이동 설정과 전투 상태 사이의 연결을 수정했습니다.

### 전투 입력 및 협업

- 공격 입력을 캐릭터에서 전투 컴포넌트 요청으로 전달했습니다.
- 가드 시작·종료를 나눠 `RequestCombatBlock(true/false)`에 연결했습니다.
- 관전 코드는 직접 테스트했으나 정상 동작하지 않아 제거했습니다. 팀원이 맡은 관전 구현을 개인 성과로 기록하지 않습니다.
- 엑셀·CSV 기반 값 편집 연동은 아직 설계 단계입니다.

**검증 한계** Steam 세션의 외부 접속 성공, 최종 네트워크 이동 일치, 완성된 게임 출시를 확정 성과로 적지 않습니다.

## 03. ChatX

**분류** Unreal C++ 멀티플레이 숫자 야구 실습 / 2026년 10월

**게임 규칙** GameMode에 1~9의 중복 없는 세 숫자 생성, 입력 검사, Strike·Ball 판정, 시도 횟수와 종료 처리를 배치했습니다.

**통신 구조** 소유 클라이언트의 Controller에서 서버로 채팅을 전달하고, 서버에서 각 PlayerController의 Client RPC로 필요한 메시지를 전달하는 경로를 작성했습니다.

**상태 데이터** PlayerState의 이름·시도 횟수 및 관련 프로퍼티의 복제 설정, GameState의 접속 알림 구조를 학습·작성했습니다.

**배운 점** 서버가 가진 상태와 소유 클라이언트의 UI, 서버에서 실행되는 RPC와 클라이언트에서 실행되는 RPC를 구분해야 했습니다.

**검증 한계** 코드 작성 근거가 중심이며 전체 게임의 최종 안정성은 별도 테스트 자료가 필요합니다.

## 04. 팀 TextRPG

**분류** C++ 콘솔 RPG 팀 프로젝트 / 2026년 7~8월

**담당** 상점 구매·판매, 아이템 구조, Logger 데이터 기록

**구조 개선** Shop과 Item을 분리하고 `std::unique_ptr<Item>`으로 아이템 수명 관리를 다뤘습니다.

**협업 경험** Git 브랜치·PR·병합과 충돌 해결을 경험했습니다. 매일 진행 상황 공유의 장점을 느꼈고, 초기에 기능 범위와 인터페이스를 더 구체적으로 맞춰야 한다는 회고를 남겼습니다.
